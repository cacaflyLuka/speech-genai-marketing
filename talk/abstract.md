# 主辦方提交用｜主題與大綱

## 主題

**從 Demo 到上線：零售生成式 AI 的 Prompt 與評測**

副標（選用）：Gemini × GEAP 實作

> 備選一：**你怎麼知道 AI 變好了？零售生成式 AI 的評測實戰**（記憶點強）
> 備選二：**生成式 AI 落地零售：Gemini 應用與評測**（最四平八穩）

## 一句話簡介

多數生成式 AI 專案卡關，不是模型不夠好，而是團隊裡沒有人能說清楚「什麼叫好」。
本場以零售商品文案為例，走完從 Prompt 設計、API 串接到評測流程的完整路徑。

## 大綱

**1　為什麼 AI demo 上不了線**（5 分）
- 同一個商品、兩段 AI 文案，現場投票必定分歧
- 專案卡住的主因不是模型，是沒有人能定義「好」

**2　GCP 工具地圖：依階段劃分，而非產品線**（8 分）
- 探索期 — GEAP Studio：不寫程式，先驗證可行性
- 整合期 — Gemini API vs GEAP 怎麼選（資料落地、計費歸屬、合規）
- 上線期 — 評測與監控

**3　Prompt 是規格書，評測是驗收**（12 分）
- Prompt v0 → v3 演進，每版只加一件事，改善可歸因
- 三層評測：規則層（含台灣廣告法規禁詞）→ LLM judge → 人工抽樣
- 為什麼改用二元 rubric，不再用 1–5 分評分
- Build vs Buy：什麼該自己做、什麼該買現成的

**4　成本與導入路徑**（5 分）
- 成本估算公式與降本四招
- 評測本身的成本，是最常被漏算的一筆
- 90 天導入路徑

**實機演示**（12 分）
- 零售文案 pipeline：生成 → 評測 → 版本對比表
- 聽眾可帶走的 Colab notebook

**QA**（3 分）

## 聽眾收穫

- 一套可直接套用的評測流程，與一份能改的 Colab notebook
- Gemini API 與 GEAP 的選型判準
- 生成式 AI 專案的成本估算方法

**適合對象**：新創創辦人、PM、工程師（不需具備 ML 背景）
**時長**：45 分鐘（含 Demo 與 QA）
