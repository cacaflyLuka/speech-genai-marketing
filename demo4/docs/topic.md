# 你怎麼知道它變好了? 主軸設計

## 主軸說明

**講題**(2026-08-20 使用者指定):從 Demo 到上線:零售生成式 AI 的 Prompt 與評測
　　封面在冒號處拆成主標「從 Demo 到上線」+ 副標「零售生成式 AI 的 Prompt 與評測」。
**核心提問**:你怎麼知道它變好了? —— 不上封面,第 6 頁第一次出現、末頁回扣。
**原副標**「一條零售文案 pipeline 的四次改版」已不使用。

核心訊息(聽眾走出場只要記得這一件事):

> **生成式 AI 的難處不在叫模型,而在你怎麼知道它有沒有變好。**

整場是一條敘事線:現場先為「哪篇文案比較好」分裂 → 承認我們沒有共同的判準 →
四版 prompt 每版只加一件事,讓改善可歸因 → 三層評測把「好」變成可量測的東西 →
數字回頭打臉,四版裡只有一版統計成立 → 實機跑一次 → 帶走第一個評測迴圈。
每段結束前回扣一次核心訊息。

## 候選方案記錄

訪談時提出兩輪、共六組。第一輪(數字驅動「32%→62%」、問題驅動「創辦人會問的四個問題」、
事故驅動「五個我踩過的坑」)使用者全數退回,要求靠回原本那條證明線;第二輪三組皆以該線為
基準、只在開場與重心上分歧,使用者選定 A。

| 方案 | 主題／副標 | 大綱骨架 | 採用/未採用理由 |
|---|---|---|---|
| **A(採用)** | 你怎麼知道它變好了?／一條零售文案 pipeline 的四次改版 | 投票 → 四版 prompt → 三層評測 → 結果 → demo → 第一個迴圈 | 「證明」這條軸線讓創辦人拿到上線判準、工程師拿到迴圈作法,兩種聽眾都不空手;開場的舉手投票是全場唯一的強互動點,能在 30 秒內讓「我們沒有共同判準」成為現場的共識而不是講者的宣稱 |
| B | 同主題,開場改用 v0→v3 對比表 | 對比表進場 →(其後同 A) | 省掉互動風險、一上台就是真數字;但「分歧」變成講者單方面陳述,失去 A 那個由現場自己製造出來的破題 |
| C | 同主題,顯著性拉到重心 | 投票 → 四版 → 三層評測 → **顯著性自成論點(7 分)** → demo → 迴圈 | 工程師拿到最多;但台下一半沒有 ML 背景,信賴區間佔到 7 分鐘會讓創辦人那半場掉線 |

第一輪被退回的三組(不採用,留檔備查):

- **32% → 62%,然後呢**(數字驅動):全場圍繞可直接上架率一個數字,收尾收在「剩下的 38% 是誰」
- **創辦人會問的四個問題**(問題驅動):能上線嗎／會不會出事／要花多少／下一版真的更好
- **五個我踩過的坑**(事故驅動):考卷出錯、評審是自己人、3% 是雜訊、便宜的是模型、改一行 prompt 數字全作廢

## 聽眾輪廓

- **範圍規模**:新創加速器場,約 40–60 人;創辦人／PM 與工程師大約各半
- **技術能力**:mixed —— 不預設任何人有 ML 背景,但台下一定有工程師會抓細節
- **已知**:LLM 會寫文案、多半玩過 ChatGPT;知道 GCP 是雲端供應商;知道「上線要小心」但講不出小心什麼
- **未知**:
  - 不知道「評測」是可以工程化的東西,更不知道評測本身會產生可觀成本
  - 不知道 rubric 用二元判準與用 1–5 分的差別在哪
  - 不知道台灣廣告法規禁詞(食安法 §28)會直接變成上線風險
  - 不知道「A 版比 B 版高 3%」多數時候是雜訊而不是進步

  - 創辦人／PM — 我怎麼知道這東西能不能上線、會不會出事;要花多少錢、多久、誰負責
  - 工程師 — 評測迴圈怎麼建、二元 rubric 怎麼寫、judge bias 怎麼壓、顯著性怎麼算

## 投影片風格

**風格基底:`keynote-impact`(主題演講/行銷風)。**
選擇理由:`event-type` 是 keynote,`styles.md` 對 keynote 的預設推薦就是 `keynote-impact` ——
本場採用基底預設。核心訊息(「你怎麼知道它變好了」)本身是一句話,適合大字置中獨佔一頁反覆回扣;
四版對比、0%→98% 這類數字也是「一頁一擊」的天然素材。

**偏離基底的決定**:

1. **基底說**「深色底 + 亮色字是常見選擇」,**本演講改為**淺色底,
   **因為** 主辦方提供的場次底圖是淺色系,深色底會把底圖與烤在其中的 logo 一起吃掉;
   加速器場地的投影條件也不明,淺色底最保險。
2. **基底說**「`--c-accent` 飽和搶眼」,**本演講改為**沿用 POC 既有的藍與橘,
   **因為** demo 的 notebook 儀表板用的就是這組色,跨媒介必須看起來是同一套;
   橘本身已足夠搶眼,不再另尋更飽和的顏色。
3. **基底說**「列表少用 —— 超過 3 點就該拆成 3 頁」,**本演講**主線遵守、
   **但**允許全場 3–4 頁標為**技術頁**(右上角標、正文降一級)承載較密的清單,
   **因為** 講者要突顯工程實作細節、台下工程師會抓細節;明示標記讓創辦人知道這頁可以放輕鬆。
4. **基底說**「divider 可省略(用 center 大字頁自然轉場)」,**本演講保留 divider**,
   **因為** 台下一半沒有 ML 背景,「我們走到哪了」的明確路標比純視覺轉場更能讓人跟上;
   代價是 divider 那幾頁不掛底圖(見「投影片分層」)。
5. **基底說**「背景是主力之一,`--bg-opacity` 0.5–0.8」,**本演講改為**全不透明且不逐頁調強弱,
   **因為** 主辦方 logo 烤在底圖裡,調淡背景會一起調淡 logo。理由見下一節。
6. **基底說**「標題本身可以是視覺主角(大、粗、佔畫面)」,**本演講遵守但加一條限制**:
   數字類的標題一律附單位與母數(如「50 篇裡 16 篇」而不是「32%」單獨出現),
   **因為** 這場的主張是「數字要能被檢驗」,自己的投影片先做到。

**視覺風格關鍵字**:淺色明亮、一頁一擊、大字置中、藍橘雙色單點強調。

**色票語意**(實際色值住 `talk/src/theme.css`,本節不抄一份):

| 角色 | 用在哪 |
|---|---|
| 背景 | 純白 —— 場地投影條件不明,純白最保險 |
| 正文 | 深灰藍,比純黑溫和 |
| 次要文字 | 圖說、來源、註解 |
| 主色 | 頁面標題、divider 轉場頁底色、圖形主線條(POC 藍) |
| accent | 全頁唯一的核心數字或法規警示(POC 橘) |
| surface | 卡片、表頭、程式碼區塊底色 |

改色只改 `theme.css` 的 tokens,不在單頁寫死色值;SVG 內的色碼是手抄的,改色票要跟著重抄。

### 三個刻意的偏離,以及它們的成因

**一、背景不降透明度**(layers.md 建議壓淡,這裡維持全不透明)。
因為**主辦方 logo 是烤進這張底圖裡的**,不走前景角標;調淡背景會一起把 logo 調淡,
而那是主辦方識別,不能淡。底圖本身的色塊已經夠淺、又集中在對角,全不透明也不搶第一眼。

**二、逐頁調強弱在這份 deck 用不上。**
調弱會讓贊助 logo 變淡;在「不降透明度」的前提下調強沒有作用。
所以 layers.md 建議的「圖表頁、截圖頁、密集表格頁一律關背景」**在這裡只對 divider 適用** ——
底圖夠淡,那些頁面直接沿用預設背景。

**三、`keynote-impact` 的「背景是主力」在這份 deck 做不到。**
基底預期背景是論點的放大器(大面積色塊、照片、逐頁換強度),但本場的背景是**主辦方素材**,
語意固定為「這是誰辦的場」,不參與論證。視覺衝擊全部得由前景承擔 ——
大字、大數字、單張大圖,不靠背景幫忙。

### 不放背景的頁型

- **divider 段落轉場頁**:維持實色藍、不掛底圖 —— 淺色底圖疊在實色藍上會糊掉,
  而彩色 logo 疊在藍底上會直接消失。其餘頁都帶 logo,主辦方曝光足夠。
- 其餘頁型一律沿用預設背景(理由見上面的偏離二)。

### 素材來源

- 主辦方提供的場次底圖,存於 `talk/assets/bg-cacafly.png`;不是我們畫的,不改內容也不改色。
- **要根治就得換素材**:請主辦方提供「**不含 logo 的底圖** + **獨立的 logo 檔**」。
  拿到之後 logo 走前景角標,背景強度就能自由調、逐頁關背景也能用,
  內容區為 logo 保留的安全區可以直接取消。
  **另一個換素材的理由**:現有這張的寬度小於版面寬度,放大後 logo 邊緣會微軟 ——
  投影看不出來,PDF 與 pptx 分發放大看得出來。順便要一份解析度更高的。

### 前景固定角標

- **無** —— 主辦方 logo 已經烤在背景底圖的右下角,前景不再放一份。
  代價是所有頁面的內容下緣都必須停在 logo 上方,這個安全區由 `theme.css` 保留;換素材後可移除。
- **頁碼放左下**(右下永久留給主辦方 logo)。

## 文字規範

執行期唯一合法的文字技法選單。`/section-impl` 與 `/page-adjust` 只能從這裡選用,不得自創;
確有規範外的需求,回 `/topic-design` 加進本節。本節只定**語意**(哪個級別用在哪個情境),
級別的實際大小住在 `theme.css`,要調大小是改 theme.css,不改本節。

### 字級(theme.css 的級別 → 使用情境)

| 級別 | 用在哪 |
|---|---|
| h1 | 封面主標、divider 轉場頁的段落名、`center` 大字頁的那一句話／那個數字 |
| h2 | 每頁頁面標題(一頁一個,固定左上) |
| h3 | 格內小標 —— 只在切格且每格需要組名時用 |
| 正文 | 條列、段落文字 |
| 技術頁正文 | 技術頁自動降一級(見「投影片風格」偏離 3) |
| small/caption | 來源、註解、圖說、圖例說明行 |

### 強調方式(每種只綁一個用途,一頁 accent 最多一處)

| 寫法 | 用在哪 |
|---|---|
| `<span class="accent">` | **主力**(基底特性)。全頁唯一的核心數字或法規警示(如 `0% → 98%`、`罰 60–500 萬`) |
| `**粗體**` | 句中關鍵術語首次出現、對比句的兩端(如「不是 X,是 Y」的 X 與 Y) |
| `<u>底線</u>` | 要求聽眾記住的結論句 —— 每段最多一句,全場不超過 6 處 |

術語首現一律附白話對照,寫法固定為 **粗體術語** + 全形括號白話,
例:**二元 rubric**(每題只能答是或否的考卷)。

### 列表符號(符號 = 語意)

| 符號 | 語意 |
|---|---|
| `-` 圓點 | 無順序的並列要點;每點不超過一行,一頁不超過 3 點(基底要求) |
| `1.` 編號 | 有先後或優先序的步驟;也用於截圖加註圖的圖例編號 |
| `✓ / ✗` | **只**用於通過/未通過的二元對照(評測結果、上線檢查),不用於一般優缺點 |

字級的實際大小、行距等排版值住在 `theme.css`(視覺數值的唯一真相),不逐頁覆寫。

## 演講風格

- **敘事型**:一條故事線帶到底(現場分裂 → 沒有判準 → 四次改版 → 數字回頭檢驗 → 你的迴圈)。
  不用「議程頁 → 一二三四」的目錄式推進。
- **語氣**:第一人稱、講自己踩的坑;保守陳述統計結論,不放寬用詞。
- **投影片上的句子,三選一**(2026-08-20 使用者要求,全簡報適用):
  ①**可查證的事實**(數字、法條、程式碼)—— 附母數或出處;
  ②**明講前提的判斷** —— 寫出「在這批 50 筆上」「我們的作法是」;
  ③**問句**。
  **不寫沒有主詞的斷言**(「就不該上架」「會讓你被罰」「就不要花錢問模型」)——
  台下有權問「誰說的」,答不出來的句子不上投影片。
- **禁用公式化句型**:「X 不是 Y,是 Z」「A 不等於 B」這類反轉句,全場最多一處。
  原本 40 頁裡出現 12 次,是最明顯的 AI 痕跡,而且每一次都在替聽眾下結論 —— 要講就直接講。
- **標題不掛「我」**:自曝的段落把認錯留給口頭與內文,標題只描述情境(如「如果出了一張爛考卷」)。
- **互動**:開場舉手投票(section-01)是全場唯一的強互動點;之後每段結尾用一句提問收束。
- **節奏**:依基底,每頁 20–60 秒、翻頁快;除 section-01(封面即路標)外,每段以 divider 開場作路標(偏離基底,見「投影片風格」4)。
  高認知負荷的段落(section-03、section-04)之後各安排一頁低密度的 `center` 回扣頁當喘息。
- **備註密度**:每頁 1–5 行提醒,只寫要點順序、關鍵措辭、數字與時間警戒,不寫逐字稿。
