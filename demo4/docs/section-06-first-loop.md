# Section 06:first-loop

## 段落定位

前面五段證明了「評測做得起來」。這一段負責讓台下**明天就動得了手** ——
把三層評測縮到一個週末做得完的規模。

對主軸的貢獻:核心訊息是「你怎麼知道它有沒有變好」。這段回答它的下半句 ——
**那我該從哪裡開始知道**。最後一頁把核心訊息原句還回去,與 section-01 首尾呼應。

拿掉會怎樣:整場變成一個做得很完整的案例分享,台下鼓掌但帶不走東西。

**討論方向**:操作導向 —— 每一步都要說得出「今天下午就能做完的那個版本」。

## 內容要點

1. **迴圈長什麼樣**(新知,本段主圖)。
   寫規則 → 出考卷 → 人工校準 → 回頭改 prompt → 再跑一次。
   重點是**它是個圈不是一條線**:評測不是專案結束前的驗收關卡,是每次改動都要跑的東西。
2. **第一步:先寫規則層**(新知,可執行性最高)。
   今天下午就能做完,而且免費。從最痛的三條開始,不要一次寫七條:
   長度、必含關鍵字、禁詞。**能用規則判的就不要花錢問模型。**
3. **第二步:出一張二元 rubric**(新知)。
   每題只能答是或否;**所有版本共用同一張考卷**,否則版本之間不能比。
   rubric 從商品資料生成、不看被評的文案 —— 而且**生成 rubric 的時候要告訴它通路限制**
   (我就是在這裡跌過)。
4. **第三步:人工只補機器判不了的**(新知)。
   語調、說服力這種東西沒有規則寫得出來。人工的角色是抽驗與校準,不是全量複審。
5. **生成的東西不好,先分辨是哪一種**(新知,本段最反直覺的一頁)。
   多數團隊碰到「AI 寫得不好」的第一反應是換模型或改 prompt,但那是三種不同的病:
   - **形狀錯**(欄位缺、超長、不是 JSON)→ 規則層抓,通常是 structured output 沒開
   - **內容錯**(規格寫錯、賣點空洞)→ judge 層抓,才是該回頭改 prompt 的
   - **法規錯**(療效宣稱)→ 規則層抓,而且要當成硬性阻擋不是提醒

   分不出是哪一種,就會用錯的方法修錯的病。三種各自對應前面金字塔的哪一層。
6. **回扣**:你怎麼知道它變好了?—— 現在你有辦法回答了。
   同一句話、同樣的排版,與 section-01 最後一頁首尾呼應。

**討論中被拿掉的點**:
- **成本不在本段開頁**(使用者決定):成本改在 section-05 的儀表板環圈圖上口述帶過。
- **90 天導入路徑不放**(使用者選了「先分辨哪一種」那頁)。
  notebook 的收尾有這張,想深究的人自己會看到;台上放進來會讓 6 分鐘變成趕場。

## 先備知識

- **聽眾**:需要 section-03 的三層框架(第 5 點的三種病直接對應那座金字塔)
  與 section-05 剛看過的實跑畫面。三個步驟都不需要新術語 —— 本段刻意零新名詞。
- **講者**:三步驟的每一步都要準備好「最小可行版本」的具體說法
  (規則層三條、rubric 十題、人工抽驗二十筆),被追問時給得出數字。
  爛考卷那件事在 section-03 已經講過,這裡只用一句話回指,不重講。

## 規範外需求

無。最後一頁與 section-01 末頁刻意**同句同版型**,那是規範內的重複使用,不是新技法。

## 備註要點

- **銜接**:接 section-05 的「這套東西你今天就能開始做」—— 第 2 頁直接給迴圈圖。
- 三個步驟每一步都要說出**最小可行版本**:規則層三條、rubric 十題、人工抽驗二十筆。
  「先做小的」比「做對的」更重要,講出來。
- 第 4 頁提到通路限制時,一句話回指 section-03 的爛考卷即可,**不要重講一次**。
- 第 6 頁是本段最有價值的一頁,不要因為在最後就趕 —— 三種病各給一個具體例子。
- 第 7 頁:**停三秒再說話**。這句話在 section-01 出現過一次,現在它有答案了。
- **時間警戒**:6 分鐘 8 頁,平均 45 秒。前面段落若超時,可壓縮的是第 3–5 頁
  (三步驟可以合併講),**第 6、7 頁不能砍**。
- **收尾**:第 8 頁停著進 QA。成本、90 天路徑、信賴區間怎麼算、中文 token 密度
  都是備而不用的 QA 彈藥。
