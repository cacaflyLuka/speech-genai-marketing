# Section 04:eval-results

## 段落定位

工具做好了,現在公布成績 —— 然後**立刻檢驗這份成績自己**。

對主軸的貢獻:核心訊息說「你怎麼知道它有沒有變好」。前三段建立了量測方法,
這一段負責回答最後一步 —— 量出來的差異,**有幾格真的算數**。
這是全場唯一一次把方法論用在自己身上,拿掉的話整場就只是「我做了一套評測,你看數字漲了」。

**討論方向**:對比取捨 —— 先給漲幅,再給可信度,兩者放在同一段裡才有張力。

## 內容要點

1. **規則層:六條全過的從 50 篇裡的 0 篇變成 49 篇**(新知,本段最乾淨的數字)。
   四版的「全數通過」比率:v0 0%、v1 0%、v2 0%、v3 98%。
   前三版都卡在同一個地方 —— `schema_valid` 是 0%,v3 一次補上(**0% → 100%**)。

   > 實作修正(2026-08-20):原本把 `seo_length_ok` 也當成「前三版卡住的另一條」。
   > 但 `poc/src/report.py` 的 `PARSER_DEPENDENT` 明講:`bullet_length_ok` 與
   > `seo_length_ok` 在自由文字上量到的是 **parser 的成功率**,不是模型的合規率,
   > 一律標成「不可測」而不是 0%。投影片照這個判斷做:表格只列四條不受 parser 影響的
   > 規則 + 全數通過,那兩條寫進圖說說明「量不到 ≠ 不合格」。
   > 另依 topic.md「數字要附母數」的規定,標題寫「0 篇 → 49 篇」而不是「0% → 98%」。
2. **評審層:漲了,但漲得不一樣**(新知)。
   rubric 通過率 73.1 → 78.0 → 86.8 → 85.4%;
   可直接上架 32% → 48% → 64% → 62%;
   critical 違反數 27 → 18 → 9 → 13。
   **v3 在評審層是往下的** —— 這一點不能藏,它正好是下一頁的引子。
3. **四次改版,只有一次算數**(原為本段主論點;**2026-08-20 起改為純口述**,不再有頁面)。
   只有 **v1→v2** 在 rubric 上統計成立(+8.86pp);v0→v1 與 v2→v3 的信賴區間都跨過 0。
   **不畫誤差棒** —— 用顏色 + 文字結論表達,誤差棒對這批聽眾太難讀。
4. **「分不出差別」不等於「一樣好」**(措辭紀律;**2026-08-20 起改為純口述**,不再有頁面)。
   是「還沒有證據說誰比較好」,不是「兩版一樣」。這句話要說得慢。
5. **那 v3 到底買到了什麼?**(承接第 2 點的往下;**2026-08-20 起改為純口述**,不再有頁面)。
   v3 沒有讓文案**變好**(−1.43pp 在雜訊內),是讓文案**變得可用** ——
   可機器讀取 0% → 100%。這是兩件不同的事,評測分開量才看得出來。
6. **回扣**:一張每格都完美遞增的表,通常代表有人在調數字。
   我們這張沒有,所以它可以被相信。

**討論中被拿掉的點**:
- **誤差棒**(使用者明確要求拿掉):95% CI 的視覺呈現改成「顯著的那一段用強調色 + 一行文字結論」,
  區間數值(+8.86pp、[+4.57, +13.15])用**講的**,不上投影片。
- 「350 次檢查、單次翻轉 0.29pp」那組解析度數字不放 —— 它跟顯著性差一個數量級,
  在 5 分鐘裡講不清楚反而會被誤當成誤差。被 QA 問到再講。

## 先備知識

- **聽眾**:需要 section-03 的三層框架(否則「規則層」「評審層」是空詞)。
  不需要懂信賴區間 —— 本段刻意不解釋 CI 怎麼算,只用「這一格的差距大到不可能是運氣」帶過。
- **講者**:所有數字必須來自實際跑出來的 `poc/data/eval_results.json`,
  一個都不准手寫。要重算就 `uv run python poc/run_eval.py --replay --limit 50`(零網路、零成本)。
  **eval_results.json 本身也可能過期** —— 上台前跑一次確認圖上的數字對得起來。
