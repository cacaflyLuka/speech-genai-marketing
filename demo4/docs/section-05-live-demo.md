# Section 05:live-demo

## 段落定位

前四段的每一個數字都是**投影片上的字**。這一段負責把它們變成**螢幕上跑出來的東西**。

對主軸的貢獻:核心訊息是「你怎麼知道它有沒有變好」—— 如果連講者自己的數字都只能靠相信,
這場演講就自我否定了。這段是全場唯一的**自我驗證**。

拿掉會怎樣:整場退回成「一個人講他做過的評測」,而不是「你可以自己跑一次的評測」。

**討論方向**:示範型 —— 投影片只負責進場與收束,中間七分半鐘全在 notebook 上。

## 內容要點

1. **等一下你會看到三件事**(路標,複習性質):
   生成(§2)→ 三層評測(§3)→ 總覽儀表板(§6)。與前面三段一一對應。
2. **全程離線重播**(新知,本段的可信度基礎)。
   `OFFLINE_MODE = True`,重播事先對真實 API 錄好的 fixtures ——
   **零網路、零成本,數字與錄製那輪完全一致**。
   這不是為了省錢的權宜之計,是為了讓「同一份輸入永遠得到同一份輸出」——
   評測要能重跑,結論才站得住。場地網路掛掉也照跑。
3. **§2 生成**:同一個商品(HB-1001),v0 與 v3 並排,肉眼比對。
   台下已經在 section-01 看過這兩篇 —— 這裡是**現場把它們生出來**,不是再讀一次。
4. **§3 評測**(本段主體,佔最多時間):
   規則層對比表 → **違規細節**(證明這不是假資料)→ rubric 逐條檢查 →
   最常沒過的判準 → 合併對比表。
   「最常沒過的判準」那格是重點:**那才是能拿去改 prompt 的東西**,通過率本身不能。
5. **§6 總覽儀表板**:前面所有數字畫成一頁 BI 報告,**不重算任何數字** ——
   圖上的數字跟表格對不上就是 bug。
6. **成本在這裡順手講**(不另開投影片頁,使用者決定)。
   儀表板裡有一格是成本環圈圖(生成 / 產生 rubric / 逐條檢查)——
   **講到那一格時口述**:整輪 50 筆 × 4 版跑下來 US$1.4987,而且**評測比生成貴**。
   金額是執行結果印出來的,不是寫在投影片上的 —— 這件事本身就是論點。
7. **收束**:剛剛螢幕上跑出來的數字,跟 section-04 投影片上的那張表**是同一組**。

**討論中被拿掉的點**:
- **§4 場景 B(評論洞察 + BigQuery)不跑** —— 與主軸無關,是 POC 的另一條支線,
  9 分鐘裡進來會讓 demo 失焦。
- **§5 成本那一節不跑**(使用者決定):成本改成在 §6 儀表板的環圈圖上口述帶過。
  中文 token 密度與降本四招留給 QA。
- **§7 錄製 fixtures 不碰** —— 台上碰到它就代表 `RECORD_FIXTURES` 被打開了,那是事故。

## 先備知識

- **聽眾**:需要 section-03 的三層框架與 section-04 的那張表 ——
  否則螢幕上跑出來的東西只是「一堆數字滾過去」。不需要看得懂 Python;
  講者要口述每一格在做什麼,不要讓台下讀程式碼。
- **講者**:
  - **`OFFLINE_MODE = True` 是最容易忘的一項**,上台前確認,且 `RECORD_FIXTURES` 必須是 `False`
    (兩者不能同時為 True)。
  - notebook 是 `poc/src/` + `poc/data/` 產生的**產物**,不要手改;改完 src 一律 `make all`。
  - 台上會有人注意到「這張是 12 個商品,樣本太小」——
    **先講,不要等被問**:真正的結論來自另外跑的 50 筆評測集。
  - 上台前跑一次確認儀表板的數字與 section-04 投影片對得起來。

## 備註要點

- **銜接**:接 section-04 的「這些數字不是我畫在投影片上的」—— 第 2 頁直接說「現在跑一次」。
- 第 2 頁**一定要講** `OFFLINE_MODE = True` 這件事,並說清楚它是為了**可重跑**,不只是為了省錢。
- §3 跑到「最常沒過的判準」時停一下:**那才是能拿去改 prompt 的東西**,通過率本身不能。
- §6 儀表板出現時,指著成本環圈圖口述:**評測比生成貴**。金額不上投影片。
  **螢幕上那個數字是 US$0.3654(12 筆那輪)**,US$1.4987 是 50 筆評測集那輪 —— 講的時候要分清楚,
