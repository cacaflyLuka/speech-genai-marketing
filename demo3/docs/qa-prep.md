# QA 準備

投影片刻意不放、但台下會問的東西。時間帳留了 **8 分鐘**給 QA
(`topic.md`「時間帳」),大約夠答 5–7 題。

**通則**:不確定的就說要查,不編(`topic.md`「講者先備知識」)。
金額一律說「看 notebook §5 跑出來的數字」,不要背 `config.py` 裡的價格 ——
那些是佔位值,而且會過期。

---

## Q1. 「這四版我是不是要照著跑一次?」

**不用,你上線就用第四版。**

這四版是我的 **git log**,不是給你的 SOP。沒有人刻意先寫一個爛 prompt ——
實際順序是:你寫你當下最好的那版 → 跑 50 筆 → 發現 13 筆標題超長 → 改一次 →
下週發現下游程式解不開輸出 → 掛 schema。回頭看,它才長成一座階梯。

台上那四版存在的唯一理由是**歸因**:四版之間只有一個變因,所以 section-04
量出來的差異才有地方可以歸。它證明的是「歸因做得到」,不是「請你從爛的開始」。

> 這題台上第 7 頁(section-02)已經用一句話擋掉了。如果還被問,代表那句話沒講清楚,
> 彩排時要加重。

## Q2. 「換一個產品要不要重新設計一次 v0→v3?」

不用。分成可複用與要換的兩堆:

| 跨產品可複用 | 每個產品要換 |
|---|---|
| 四類約束本身:通路約束、法規禁令、品牌語調、結構化輸出 | **禁詞清單** —— 依商品的 `regulated_category`(保健食品走食安法、化粧品走化粧品法,兩份清單不同) |
| 三層評測的架構(規則 / 評審 / 人工) | **字數預算** —— 依通路;這個沒給對會直接毀掉 rubric(見 Q7) |
| 二元 rubric 的寫法與「共用同一份考卷」的紀律 | **few-shot 範例** —— 要換成該品類自己的合規文案 |

作法:新產品從**你現在最好的那一版**分支出去,跑一次 50 筆,看哪一類先破。
通常不是四類全破,是一類。破的那一類才需要回到「一次只改一件事」。

## Q3. 「溫度要不要調到 0?」(工程師會問)

先拆開「穩定」這兩個字,溫度只對其中一種有用:

- **形式的穩定**(長度合規、禁詞、JSON 解得開)—— **溫度是很弱的槓桿**。
  溫度 0 不會讓約束成立,只會讓違規變得比較一致。禁詞在溫度 0 照樣出現,
  只要 prompt 沒擋住它。這裡的正確槓桿是**閘**:結構掛 `responseSchema`、
  禁詞交給規則層。溫度也只是一個請求。
- **用字的變化** —— 這才是溫度真正控制的東西。

**溫度 0 對行銷文案有具體代價**:200 個 SKU 會長得像同一句話。
商品資料不同所以字面不同,但開頭句式與節奏會收斂。

**而且溫度 0 也不是真的可重現**:託管模型走 greedy decoding 仍會跨次數飄
(批次的非決定性、`-latest` 這種 alias 背後換版)。真的要每次都一樣,做法是把輸出存起來 ——
那正是這個 POC 的 fixtures 在做的事。**要可重現就快取,不是調溫度。**

### 這個 POC 為什麼是 0.4

`poc/src/config.py` 寫的理由是「用低溫,降低失敗機率」,但更重要的理由沒寫在那裡:
**它在 v0→v3 四版之間是固定的。** 溫度是一個變因;要是順手在 v2 把它從 0.4 調到 0.8,
那座階梯就什麼都不能證明了。

所以順序是:**做 prompt 的時候把溫度凍住;prompt 定了之後,溫度自己當一次實驗,量同一批 50 筆。**

抽取與評審用 0.0(`JUDGE_TEMPERATURE`、`insights.py`)—— 那些任務要的正是可重現,不是創意。

## Q4. 「生成 5 次再挑一篇,是不是更好?」

方向對,但它跟溫度是兩個不同的機制,而且有兩個前提:

1. **選擇器必須比隨機好。** 用 LLM judge 選,就繼承它的偏誤;更麻煩的是這裡的 rubric 是
   **二元**的,它量的是「上不上得去」而不是「寫得好不好」。當 5 篇候選全部通過每一題,
   選擇器就沒有解析度了 —— 你以為在挑最好的,其實在天花板上隨機挑。
   **這是二元 rubric 真實的限制,被問到就承認。**
2. **成本不是 5 倍生成,是 5 倍整條帳。** 生成是便宜的那一層(flash),評審才是貴的
   (2.5-pro,單價高一個檔次)。5 篇都送給評審選,多花的錢主要在評審。

**便宜的版本**(建議這樣答):

```
溫度 0.7–0.8 生成 3 篇
  → 規則層篩(免費、毫秒級:禁詞 / 長度 / schema)
  → 取第一篇存活的
```

變化度與合規都拿到,成本是 3 倍生成 + **0 倍評審**。
等到有一份能在「合格」之上分高低的 rubric,再讓評審參與挑選。

> **誠實邊界**:`poc/src/` **沒有實作 best-of-n**(沒有 `candidate_count`,每筆只生成一次)。
> 這題只能答設計方向,不能說「我們量過」。

## Q5. 「生成的東西不好,就重新生成嗎?」

台上 section-06 第 3 頁講了三種壞法,這裡是加深的部分:

- **一週寫 3 篇、你自己一篇篇看** → 直接重生或手改就好。你就是評測,錯了成本是重打一行字。
  **這種情境不需要這整條 pipeline** —— 這句話要願意講,不然整場像在賣工具。
- **200 個 SKU 上架,或錯一篇罰 60–500 萬** → 「不好就重生」根本執行不了,
  因為沒有人在看第 147 篇。這時候修的不是那一篇,是生成器,然後重跑整批。

判斷分界就是台上那三欄:1 筆 → 手改;12 筆壞在同一個地方 → 規格缺口;
每篇都說不上壞 → 你還沒有尺。

## Q6. 「調不動的時候,到底是模型爛還是我描述得不清楚?」

**在你有評測之前,這兩個分不出來** —— 這就是核心訊息本身。

拆成三種失效:

| 失效 | 判準 | 解法 |
|---|---|---|
| **A. 可規格化,模型也會照做** | prompt 裡根本沒寫 | 寫進去。v0→v1 標題長度 74% → 100% 就是這種 |
| **B. 可規格化,但模型做不穩** | 寫了還是漏 | **不要再調 prompt** —— 做成閘。禁詞 v2 在 50 筆上 100%,那是結果不是保證 |
| **C. 說不出來,「我就是不喜歡」** | 講不出一條能判是非的標準 | 這個需求還不存在。拿 5 篇喜歡的、5 篇不喜歡的,把差別寫成一題是非題 |

**還有一個常見真相**:要的東西彼此衝突(30 字內 + 要有情感 + 要塞五個規格關鍵字)。
這在評測表上會直接顯示成 trade-off(一欄升、另一欄降),不是模型的錯 ——
但沒有評測你只會覺得「模型很笨」。

## Q7. 「你們的評測有什麼量不到的?」(最好由講者自己先講)

- **同質化量不到。** 三層評測都在問「這一篇合不合格」,沒有一層在問
  「這 200 篇是不是長得一樣」。溫度調低會讓這件事變嚴重,而現在的儀表板看不出來。
- **二元 rubric 在「合格」之上沒有解析度**(見 Q4)。
- **踩過的坑**:rubric 生成時沒告知通路字數預算,出現「30 字賣點塞不下」的判準,
  修正前 v0 拿 100%、v3 只有 57%。台上 section-03 第 6 頁講了,QA 追問就展開講
  「所以 rubric 生成時必須知道通路限制」。

## Q8. 統計那段(工程師追問時才展開)

- 四版裡**只有 v1→v2 在 rubric 上統計成立**:+8.86pp,95% CI [+4.57, +13.15]。
- 50 筆 × 7 條 = 350 次檢查,單次翻轉 0.29pp —— **那是解析度,不是顯著性**。
  配對比較的 95% CI 寬達 ±5pp,差一個數量級。
- 用詞守住:「**分不出差別**」不等於「一樣好」。

## 上台前的技術地雷(不是 QA,但寫在這裡免得忘)

- **改了 `GEN_TEMPERATURE` 不會讓 fixtures 失效。**
  `poc/src/generation.py` 的 `fixture_key()` 只用 (模型, prompt, 是否結構化) 當索引鍵,
  **溫度不在鍵裡**。所以調了溫度又跑 `OFFLINE_MODE`,會**靜默重播 0.4 那輪錄的輸出**,
  不會 `KeyError`。這是「寧可炸掉也不要靜默拿到舊資料」唯一失守的地方 ——
  要比較不同溫度,必須連網重錄。
- 演講當天 `OFFLINE_MODE = True`、`RECORD_FIXTURES = False`,`LOCATION = "global"`。
