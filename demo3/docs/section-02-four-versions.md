# Section 02:four-versions

## 段落定位

**存在理由**:section-01 逼出「沒有共同的尺」,但在拿尺去量之前,得先有**被量的東西**。
這段建立全場的實驗設計:四個版本、每版只動一個變因。拿掉這段,section-03 的三層評測
就會變成一個孤立的工具展示 —— 有尺沒有東西可量,而且量出差異也不知道該歸功給誰。

**與主軸的掛勾**:核心訊息說「你怎麼知道它有沒有變好」,這段回答其中的「**它**」是什麼、
以及為什麼「變好」這件事有辦法歸因。

**討論方向**:演進脈絡 —— 依 v0 → v3 的時間順序走,每一版只講「加了什麼、為什麼加」。

## 內容要點

1. **prompt 是規格書,不是咒語**(新知,本段的比喻先行)。多數人把 prompt 當成
   「要講對咒語模型才聽話」;實際上它是一份寫給承包商的規格書 —— 沒寫的東西不要期待會出現。
2. **v0:大多數人第一次寫的 prompt**(複習 + 打臉)。原文只有一句
   「幫我寫這個商品的電商文案」。產出是 section-01 的 A 版:標題超長、滿版 emoji、
   出現「告別乾荒」這類宣稱。**這一版是刻意保持這麼爛的**,它是基準線不是稻草人。
3. **v1 加通路約束**(新知)。角色、受眾、平台字數上限、必含規格關鍵字。
   修好的是「可上架」:標題長度合規 74% → **100%**、規格完整覆蓋 82% → **98%**。
   意外的副作用:法規禁詞 0 命中 80% → 98% —— 但那不是這一版的目的,只是文案變短之後
   自然少講了大話。
4. **v2 加法規禁令與品牌語調**(新知)。禁詞清單依商品的 `regulated_category` 動態帶入
   (保健食品與化粧品適用的法源不同);語調用 few-shot 給既有合規文案當範例。
   法規禁詞 0 命中率 v1 98% → v2 **100%**,但那是 50 筆的結果不是保證 ——
   **prompt 裡的禁令是請求,不是閘**,這是 section-03 規則層存在的理由。
   **(2026-08-19 補頁)** 本點原本沒有對應頁面,v2 只在階梯圖上佔一格,
   造成敘事線從 v1 直接跳到 v3;已補為段內第 5 頁。
5. **v3 加結構化輸出**(新知,技術頁)。關鍵不在 prompt 多寫一句「請輸出 JSON」,
   而在呼叫 API 時掛上 **responseSchema**(GEAP / Gemini API 的原生參數)——
   用 prompt 硬凹 JSON 會在第 200 筆的時候壞掉,用 schema 不會。可機器讀取 0% → 100%。
6. **一次只加一件事的理由**(新知,本段結論)。四版之間只有一個變因不同,所以
   section-04 量出來的差異才歸因得回去。一次改三件事然後看到分數上升,你不知道該保留哪一件。
7. **刪除的點**:原本要講 prompt 的 token 成本與快取 —— 移到 section-06 的備註,
   本段講成本會打斷演進敘事。

## 先備知識

- **聽眾**:section-01 建立的「同一模型、同一批資料,只有 prompt 不同」。
  術語 `few-shot`、`schema` 首現時要附白話對照。
- **講者**:v3 的 schema 欄位要背得出來(title / bullets / seo_description / hashtags);
  被問到「為什麼不用 function calling」時的答法先想好。

## 備註要點

- **銜接**:接 section-01 的「我要證明這句話,從我怎麼改 prompt 開始」——
  第一句「剛才那兩篇,A 是這樣來的」。
- **必須講對的數字**:74% → 100%(標題長度)、82% → 98%(規格覆蓋)、80% → 98%(禁詞,v0→v1)、
  98% → 100%(禁詞,v1→v2)、0% → 100%(可機器讀取)。全部來自 50 筆 × 4 版的實測。
- **必須講對的措辭**:v1 的禁詞改善是**副作用不是設計**;v3 是「變得可用」不是「變得更好」
  —— 這句在 section-04 會再出現一次,兩次說法要一致。
- **(2026-08-19 新增)防誤解的一句**:第 7 頁必須講「這四版是我的 git log,不是給你的 SOP,
  你上線就用第四版」。台下最容易帶走的錯誤結論是「原來我要從 v0 開始爬」——
  沒有人刻意先寫一個爛 prompt,v0→v3 是回頭看才長成階梯的改動紀錄。
  被追問「換一個產品要不要重跑一次 v0?」:不用。可複用的是**四類約束**
  (通路 / 法規 / 語調 / 結構化輸出),要換的是**禁詞清單**(依 `regulated_category`)、
  **字數預算**(依通路)、**few-shot 範例**。完整答法見 `docs/qa-prep.md`。
- **時間警戒**:第 6 頁是本段唯一的技術頁,工程師會想追問;台上點到為止,說「QA 我再展開」。
- **交棒**:第 7 頁結尾「四個版本擺在這裡了 —— 現在問題回到 section-01:你要拿什麼去量它們?」
