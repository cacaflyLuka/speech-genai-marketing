# Section 05:live-demo

## 段落定位

**存在理由**:前面 26 分鐘全部是投影片,而投影片上的數字是最容易造假的東西 ——
講者自己在 section-04 才剛講過「每一格都完美遞增的表通常代表有人在調數字」。
這段用實機執行把可信度補回來:同一份程式碼、同一批資料,現場跑一次。
拿掉這段,整場就只剩一個人在台上宣稱自己做過。

**與主軸的掛勾**:核心訊息的「怎麼知道」在這裡從方法變成**可以按下去執行的東西**。

**討論方向**:示範導向 —— 投影片退居配角,只負責「等一下要看什麼」與「剛剛看到了什麼」。

## 內容要點

1. **執行前的預告**(新知)。等一下會依序看到三件事:
   (1) 同一個商品跑 v0 與 v3,兩份輸出並排;
   (2) 三層評測跑過去,規則層秒回、評審層逐條判;
   (3) 四版對比表,和投影片上那張表對得起來。
2. **離線重播的說明**(新知,誠實揭露)。現場**不打真實 API** ——
   跑的是事先對真實 API 錄好的回應(fixtures),零網路、零成本,
   數字與錄製那一輪完全一致。這不是作弊,是把「會場網路」這個變因移除;
   要驗證的話,程式碼與 fixtures 都在 repo 裡。
3. **執行**(9 分鐘的主體)。
4. **回收**(新知,收束)。剛剛跑出來的表就是 section-04 那張表 ——
   差別只在你親眼看著它被算出來。整條 pipeline 從商品資料到對比表,
   一個人一個下午做得完。
5. **刪除的點**:場景 B(評論洞察 + BigQuery)—— 這場不跑,預設關閉;
   有人問再說。加進來會讓 demo 從 9 分鐘變成 15 分鐘。
   **金額類的內容**(這次 demo 花多少錢)也於 2026-08-19 依使用者決定全部移除 ——
   成本的說法統一收在 section-06 的成本頁,只講算法不講金額。

## 先備知識

- **聽眾**:section-02 的四個版本、section-03 的三層、section-04 的對比表 ——
  demo 不引入任何新概念,只把前面三段變成可執行的東西。
- **講者**:上台前必做 —— `OFFLINE_MODE = True`(README 標記為最容易忘的一項)、
  `RECORD_FIXTURES = False`(兩者不可同時為 True)、notebook 是
  `build_notebook.py` 的產物不可手改。改過 prompt 或模型名就要重錄 fixtures,
  否則離線重播會直接 `KeyError`。

## Demo

- **目的**:讓評測迴圈從概念變成看得見的輸出,並讓聽眾確認投影片上的數字是算出來的。
- **操作流程概要**:
  1. 開 Colab 的 speaker 版 notebook,確認 `OFFLINE_MODE = True`
  2. 跑生成 cell —— 同一個商品的 v0 與 v3 輸出並排
  3. 跑規則層 cell —— 毫秒級回應,禁詞與長度逐條標示
  4. 跑評審層 cell —— 二元 rubric 逐條判,印出通過率
  5. 跑對比表 cell —— 四版 × 指標,與 §6 儀表板
- **環境需求**:Colab + repo 既有的 `poc/` notebook(uv + python 產生);
  離線重播不需網路。不另建 `demo/` 資料夾。
