# Section 06:first-loop

## 段落定位

**存在理由**:前面五段講的是「我怎麼做的」,這段回答「那我呢」。加速器場的聽眾
不是來欣賞別人的 POC 的,他們要的是明天早上可以開的第一個 ticket。
拿掉這段,整場會停在一個漂亮但與聽眾無關的案例上。

**與主軸的掛勾**:把核心訊息從一句主張變成一組動作 —— 「你怎麼知道它有沒有變好」
的答案是:先建立最便宜的那一層,然後才有資格談其他的。

**討論方向**:可帶走的判準 + 收束 —— 三步驟起手式、一條停止規則、一張成本帳,然後收尾。

## 內容要點

1. **三步驟起手式**(新知,本段主體)。
   (1) **先寫規則層** —— 本機、免費、毫秒級,而且它擋的是罰款這種不可逆的風險;
   (2) **再寫二元 rubric** —— 從你的商品資料生成,所有版本共用同一份;
   (3) **最後才比版本** —— 而且一次只改一件事。
   順序不能顛倒:多數人是從第 3 步開始做的,所以永遠在爭論誰比較好。
2. **一條停止規則**(新知)。什麼時候該停下來收數據而不是繼續改 prompt ——
   當你**說不出下一版要加的是哪一件事**的時候。說不出來就代表你在猜,
   猜出來的改動即使分數上升也歸因不了。
3. **成本怎麼算**(新知,給創辦人的一段)。三段組成:生成(版本數 × 商品數 × token 單價)、
   產生 rubric(商品數 × token 單價,四版共用同一份)、逐條檢查(版本數 × 商品數 × 每條判準)。
   **只講算法不講金額** —— 單價會隨模型與時間變動,寫死在投影片上只會過期,
   而且金額大小的比較容易講成推銷。能動的變數只有兩個:跑幾個版本、評測集多大。
   (2026-08-19 依使用者決定,移除實測金額與「比罰款便宜」的比較說法。)
4. **收尾**(回扣)。回到開場那兩篇文案:如果現在再投一次票,你手上會多一把尺。
5. **刪除的點**:90 天導入路線圖 —— 移除。它會把結尾從「一個可以開始的動作」
   稀釋成「一張看起來很專業但沒人會執行的甘特圖」;三步驟已經是可執行的最小單位。
   (原 topic.md 大綱寫的是「你的第一個評測迴圈」,本段維持該範圍。)

## 先備知識

- **聽眾**:前五段全部。本段不引入新概念,只重新排列。
- **講者**:成本數字要能拆得出來(生成 / 產生 rubric / 逐條檢查三段);
  被問到「我的場景不是零售文案」時的答法 —— 三步驟與領域無關,
  會變的只有規則層的規則來源。

## 備註要點

- **銜接**:接 section-05 的「如果你今天回去想開始,從哪一步開始?」——
  第一句「從最便宜的那一層開始。」
- **成本頁的紀律**:講三段的算法,不講金額;現場有人要看實際金額,開 notebook §6 的環圈圖。
  三段拆法要與該圖一致。
- **必須講對的措辭**:停止規則是「說不出下一版要加哪一件事」,
  不是「分數不再上升」—— 後者會鼓勵人去追雜訊。
- **時間警戒**:這是最後一段,超時直接砍**第 4 頁**(停止規則移到 QA)。
  **第 3 頁(三種壞法)不可砍** —— 這是全段對創辦人最實用的一頁,而且「怎麼分辨」比
  「什麼時候停」更難在 QA 用一句話補完。
- **交棒**:全場最後一頁,收在核心訊息,不留新問題;接 QA。
