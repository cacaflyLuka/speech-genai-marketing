# Section 03:Prompt 是規格書

## 段落定位

**存在理由**:主張是「你怎麼知道它有沒有變好」。要回答這個問題,得先有**東西可以比較** ——
四個明確不同、而且差異可歸因的版本。這段負責造出那四個版本,並把 prompt 從
「調語氣的玄學」翻轉成「可以版本控制的規格書」。沒有這段,第四段的評測沒有受測對象。

**討論方向**:演進脈絡。v0 → v3,**每一版只加一件事**,所以第四段表格上每一欄的改善才歸得了因。

## 內容要點

1. **v0 naive**(新知):「幫我寫這個商品的電商文案」。吐出兩千多字的 markdown,文筆不差,
   但沒有一個欄位可以直接塞進商品頁。而且它自己決定寫了「告別模糊」這種話 ——
   **我沒告訴它不能寫,它就自己決定了。**
2. **v1 加通路約束**(新知):角色、受眾、字數上限、必含規格。
   為什麼要字數上限 —— 蝦皮標題 60 字截斷,文案再美被截掉就是廢的,這種事模型不會自己知道。
3. **v2 加法規與語調**(新知):法規禁詞清單 + 兩則自家既有文案當範例。
   **與其形容「溫和專業」,不如直接給兩則你既有的文案** —— 形容詞模型理解不了,範例它學得會。
   證據:左欄範例句型與右欄產出標題句型一致,而我沒有描述任何規則。
4. **v3 結構化輸出**(新知,工程師的重點):prompt 一個字沒改,加的是 API 原生的 `responseSchema`。
   **不是在 prompt 裡寫「請輸出 JSON」** —— 那樣模型會照做九成的時間,剩下一成在你上線之後才出現。
   模型是被**解碼器**約束在 schema 內的,不是被你的請求說服的。
5. **四版統整**(複習,快速帶過):四列 v0–v3,這一版多了什麼、在解什麼問題。
6. **關鍵訊息**(新知):只有 v3 能接進系統,前面三版都只是聊天。
   「看起來不錯」跟「能貼進你的 PIM」是兩件不同的事。

**紀律(不可違反)**:
- 四頁用**同一個版型、同一個商品**(HB-1001 金盞花萃取葉黃素膠囊 60 粒),
  左欄 = 這一版 prompt 加了什麼,右欄 = 它的產出。
- 文字全部抄自 `poc/`:prompt 抄 `src/prompts.py` 組出來的字串,產出抄 `demo_outputs.json` 的重播輸出。
  改過 prompt 或重錄 fixtures 之後要回來對一次。
- **這一段一個通過率數字都不放。** 評測框架要到 section-04 才登場,提早給百分比聽眾沒有框架可以接
  —— 這是實際被聽眾回饋過的問題,不要「順手補個數字更有力」。

## 先備知識

- 聽眾:需要知道「prompt」是什麼(section-01 已用兩段文案帶到);
  v3 那頁對非工程師會偏硬,靠「你不需要寫 parser 去猜」這句白話接住。
- 講者:`COPY_SCHEMA` 的實際內容要背熟,特別是**它沒有約束長度**(見備註的 QA 防守)。

## 備註要點

- **銜接**:接第二段的「同樣的工具,為什麼有人做得起來」→ 差別在你把哪些要求寫成了條件。
- 第 4 頁 **QA 防守**:「schema 是不是連長度也保證了?」→ **不是。schema 保證的是形狀** ——
  欄位在、型別對、parser 不會掛。長度寫在欄位說明裡請模型遵守,是請求不是約束。
  第四段表上 v3 可機器讀取 100%、賣點長度合規 98%,差的 2% 就是這個差別。
  ⚠️ 不要為了好講就把左欄改成 Pydantic 的 `Field(max_length=60)` —— 那會暗示一個 98% 的資料證明不存在的保證。
- 第 5 頁 20 秒快速帶過,講不完直接跳 —— 這頁是幫聽眾整理,不是新論點。
- 有人先問「哪一版比較好」→ 「等一下有 50 筆實測的表,先看 prompt 怎麼寫」。
- **交棒**(第 6 頁):現在有四個版本了 —— 哪個比較好?你怎麼證明?
